# Training-data provenance — `backend/app/ml`

## Current status: synthetic-label training data (explicit)

No labelled historical stall outcomes and no bulk historical works table
were obtainable for this prototype:

* the open-data aggregator hosting MoSPI-sourced MPLADS works tables
  (work-level sanction amounts by state/district/constituency/MP, 2005–2025)
  requires sign-in for bulk download;
* the data.gov.in API requires a registered API key.

So both models train on **synthetic data with documented ground-truth
rules**, which is legitimate for a prototype as long as it is stated
(which it is — here, in code comments, and on the methodology page):

* `stall_training_samples.csv` — 2,000 rows of engineered features
  (`months_since_sanction`, `extensions`, `disbursal_velocity`,
  `category_code`, `district_stall_rate`) with the label derived from the
  rule in `synthetic._stall_label`, plus 4% label noise. Generator seed is
  fixed, so the rows are exactly reproducible via
  `.venv/bin/python -m app.ml.train`.
* `cost_training_samples.csv` — ~4,200 rows of
  (`district`, `category`, `terrain`, `year`, `sanctioned_lakh`) sampled
  log-normally around the demo's published peer-baseline medians
  (`seed_data.COST_BASELINES`, imported — not copied — so the two cannot
  drift apart).

## Dropping in real MoSPI-published rows later

To retrain on real history, write a CSV with **exactly** these columns and
re-run `.venv/bin/python -m app.ml.train` (point it at the file — the
column contract is the only integration point, no module code changes):

```
district,category,terrain,year,sanctioned_lakh
Rangareddy,Community Assets,plain,2019,16.50
...
```

* `district` / `category` must use the demo's canonical names (see
  `models.DISTRICT_CODES` / `models.CATEGORY_CODES`); unknown values encode
  as `-1` and are still scored, with lower confidence.
* `terrain` is `plain`, `semi-hilly` or `hilly`.
* `year` is the sanction year; `sanctioned_lakh` is the sanctioned amount
  in ₹ lakh.

A suitable source is the MoSPI-published 16th/17th Lok Sabha MPLADS
sanctioned-works tables (state, district, constituency, MP, sanction amount,
work name, dates), available via data.gov.in or MoSPI-citing open-data
aggregators. Per the demo's data policy, vendored real rows must be
aggregated statistics only — never a real named MP's identifiable project
shown under a risk flag.

## Trend history

`trend_history.csv` (same directory layout, generated by
`synthetic.trend_history_frame` once added, or vendored from the same MoSPI
tables) carries `(district, year, works_sanctioned, avg_release_pct)` for
the multi-year longitudinal comparison in the Trend module.
